## Analysis

Everything below is generated by this skill, after and separate from the Raw Idea.

### Goal

Repo overrides page template (`page.html`) by mirroring it and naming it in `mdwiki.yml`, without having to also copy default `app.css` or any other theme file. CSS side already done by `stylesheet:` (cascade on top of default `app.css`); this item covers template side only.

### Verified On Release (`70a70bc`)

Only template override today: `theme: <dir>` in `mdwiki.yml`. It replaces whole default theme folder (`mdwiki/theme/`, shipped as package data, resolved via `DEFAULT_THEME_DIR`):

- Jinja templates loaded from theme dir only (`_templates_for(theme_dir)`).
- `/_assets/*` looks in theme dir, then `mdwiki/static/` (holds only `shadow-helper.js`); default `app.css` never reached.

Reproduced with content root plus `theme:` folder:

| Theme folder has | `GET /` | `GET /_assets/app.css` |
|---|---|---|
| only `app.css` | 500 (template not found) | 200, theirs |
| only `page.html` | 200 | 404, page unstyled |

So template override works only by copying both files; copy stops getting upstream changes.

### Scope

In:

- Per-file fallback for theme folder: Jinja search path `[theme dir, default theme dir]`; `/_assets/` lookup theme dir, default theme dir, then `mdwiki/static/`. Template-only theme keeps default `app.css`; CSS-only theme keeps default `page.html` (implementation exists as commit `6685937` on review branch, +43 lines, conflicts with `d5875ed` in `/_assets/` loop so needs backport).
- Decide config shape for template override: keep folder-level `theme:` (mirror any subset of theme files), or add file-level key (e.g. `template: ./wiki/page.html`) parallel to `stylesheet:`.
- Custom `page.html` contract documented: context variables it receives (`site_title`, `title`, `content`, `back_link`, `nav`, `backend_base`, `has_mermaid`, `request_path`, `stylesheet_override`), what default template does with each, which it must keep for features to work (mermaid loader, `stylesheet_override` link, backend base script).
- `validate`: template that fails to load or render reported once, not per page.

Out:

- CSS override (done: `stylesheet:`, `70a70bc`).
- Template partials/blocks (`{% extends %}` of default template) — possible follow-up once single-file override exists.
- Widget styling (Shadow DOM `widget.css`, overridden by overriding widget).
