## Raw Idea

Widget placeholder sentinel collision: page text containing the internal token MDWIKIWIDGETPLACEHOLDER<n>ENDMDWIKIWIDGETPLACEHOLDER crashes rendering (IndexError -> 500) when n is out of range of the page's macros, and is silently replaced by a real widget when n is in range. Investigate further and design a robust fix (e.g. per-render nonce in the sentinel). Note: a minimal guard exists on branch agent/autonomous-run-2026-11-23 commit 6ca5ebf (out-of-range only). Work on the `release` branch created from master.

## Analysis

Everything below is generated by this skill, after and separate from the Raw Idea.

### Goal

Author text must never be read as internal widget sentinel. Today sentinel is fixed public string, so page that spells it (for example, page documenting mdwiki internals) either 500s or gets widget it never asked for. Fix: sentinel page text cannot forge.

### Scope

In:

- Sentinel format and its matcher in `mdwiki/render.py`.
- `_extract_macros` and `_fill` agreeing on per-render sentinel.
- Tests for both failure modes (out-of-range index, in-range index).

Out:

- Macro expansion inside code blocks (separate fragility point "Macro expansion not fence-aware"; branch `agent/autonomous-run-2026-11-23` handles it in commit `b45eb1e`).
- Escape syntax for writing literal macro.
- Any change to macro syntax or `widget_markup` output.

### Verified On Master (`3b2a3ee`)

Sentinel joined below with `<T>` = `MDWIKIWIDGETPLACEHOLDER` (spelled split, so this page itself stays safe).

- Page with `<T>7END<T>`, no macros: `render_relpath` raises `IndexError: list index out of range`. Page GET 500. `mdwiki validate` reports `a.md: failed to render (list index out of range)`, exit 1.
- Page with one real `toast` macro, plus `<T>0END<T>` typed once in prose and once in inline code: output has 3 `data-widget="toast"` hosts, not 1. No error, no validate issue. Silent.

Second case is worse: quiet, and in-range index is likely (index 0 valid on any page with one macro).

### Solution Design

1. Per render, build nonce: `secrets.token_hex(8)` (lowercase hex, alnum only). Must stay alnum: Python-Markdown strips `\x02`/`\x03` (see Widget Injection Non-Obvious Solutions), and `_`/`*` would trigger emphasis.
2. If nonce appears in raw body (practically never), draw again. Sentinel then provably absent from author text.
3. Sentinel: `MDWIKIW{nonce}X{idx}E{nonce}` or same shape. Compile matcher per render with nonce embedded (`re.escape` not needed for hex).
4. `_extract_macros(body, nonce)` emits sentinel; `_fill` regex uses same nonce. Typed old-style token now matches nothing, left as is.
5. Keep `idx < len(macro_refs)` check in `_fill` as cheap defence (same as `6ca5ebf` guard).
6. Tests per Code Elements table.

Alternative rejected: deterministic sentinel derived from body hash. Reproducible output, but same input still forgeable by author who copies hash. Random nonce plus absent-from-body check is simpler. Rendered HTML does not contain sentinel, so nonce never leaks and output stays deterministic.

Contracts: no Shared Contract touched. Sentinel internal to `render.py`; browser never sees it. Site Validation reuses `WIDGET_MACRO_RE`, not sentinel, so unaffected.

Closes fragility point on [Widget Injection](../features/Widget-Injection.md): "Literal sentinel collides with placeholder", and the matching "only loud failure" line in its Fragility Note. Both pages need update in `/wiki-sync` after ship.
