## Analysis

Everything below is generated by this skill, after and separate from the Raw Idea.

### Goal

Repo is everything needed to render its wiki: pages, `mdwiki.yml`, folder named by `widgets_dir:`, plus mdwiki built-in widgets. Nothing from machine it runs on. Same checkout renders same widgets anywhere, and `mdwiki validate` gives same answer anywhere.

### Decisions (agreed in review)

1. One widget source besides built-ins: `widgets_dir:` in `mdwiki.yml`, resolved relative to config file (like `theme:`).
2. No environment-supplied widget source (no env var, no search path list).
3. `--widgets` CLI flag and its Python API equivalents go away. Testing a widget = edit, add or rename it inside repo widgets folder.
4. Repo widget may override built-in widget of same name (whole widget directory, as today). Override stays allowed; `validate` prints informational line for it, not counted as issue.
5. Environment that relies on its own widgets (harness `create-backlog-item`) is out of scope here; user resolves that elsewhere.

### Verified On Release (`d5875ed`, same widget code as master)

Widget dir entry points today, all one directory:

- `mdwiki serve --widgets <dir>` — `cli.py` `_cmd_serve` passes `widgets=` to `serve`, which passes `widgets_dir=` to `create_app`.
- `mdwiki validate --widgets <dir>` — `cli.py` `_cmd_validate`.
- Python API `create_app(widgets_dir=)` and `serve(widgets=)` — `server.py`.
- `widgets_dir:` in `mdwiki.yml` — documented in README ("Point `mdwiki serve` at your widgets directory with `--widgets <path>` (or `widgets_dir:` in `mdwiki.yml`)"), never read. Since `d48fac9` config load warns `unknown key 'widgets_dir' is ignored`.

Environment dependency shown by this repo itself: `mdwiki.yml` hooks `create-backlog-item` onto `Backlog.md`; widget exists only in container merge dir `/tmp/mdwiki-widgets-merged`. Plain checkout: `mdwiki validate --dir wiki --config mdwiki.yml` reports `mdwiki.yml: hook widget 'create-backlog-item' does not resolve under ./widgets/`; served page shows error toast. Inside container same validate is clean.

### Scope

In:

- Read `widgets_dir:` into `SiteConfig.widgets_dir` (as `fcecfa0` does), add to `KNOWN_KEYS`.
- Use it as only host source for page markup, `/_widgets/` asset route, `validate` (and `build` if it lands from review branch).
- Remove `--widgets` from `serve` and `validate`; remove `widgets_dir=` / `widgets=` from `create_app` / `serve`.
- Deprecation step first: keep `--widgets` one version, printing warning (`--widgets is deprecated; set widgets_dir: in mdwiki.yml`), still honoured; remove next version.
- `widgets_dir:` pointing at missing folder: startup warning plus `validate` issue, not crash.
- `validate` informational line per repo widget that overrides built-in, e.g. `widgets/toast overrides built-in widget 'toast'`. Not counted as issue, not failing `--strict`.
- Tests move from passing `widgets_dir=` to writing temp `mdwiki.yml`.
- README "Writing a widget" and "Site config" sections.

Out:

- Multiple widget folders, search path, env var.
- Per-file merging between repo widget and built-in widget.
- Harness/container side (`user-entrypoint.sh` merge, shipping `create-backlog-item` into repos).

### Solution Design

1. Take `fcecfa0` config part: `widgets_dir:` read, resolved relative to `mdwiki.yml`, added to `KNOWN_KEYS`. Drop its "`--widgets` wins" precedence.
2. Single source of truth: `WikiRenderer` and `_widget_assets` read `config.widgets_dir`. No second parameter anywhere, so markup, assets and validate cannot disagree.
3. Deprecation release: `--widgets` still accepted, prints one warning, overrides config for that run. Next release: flag removed, argparse rejects it.
4. Validate info block: after issues, `info:` lines for overrides of built-in names; separate from errors and warnings, never affects exit code.
5. Missing `widgets_dir` folder: `serve` warns at startup and continues (widgets fall back to error toast); `validate` reports error naming config path.

Contracts: `/_widgets/<name>/widget.js|css` URLs unchanged; widget bundles untouched. Breaking change only for callers of `--widgets` or `create_app(widgets_dir=)`, including container entrypoint (`--widgets /tmp/mdwiki-widgets-merged`) — hence deprecation step first.

Closes discrepancy where README documents `widgets_dir:` that code ignores. Supersedes commit `fcecfa0` on review branch.
