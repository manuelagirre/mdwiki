## Analysis

Everything below is generated by this skill, after and separate from the Raw Idea.

### Goal

Content root pointed at repo (or folder holding build output, secrets, drafts) must not publish what author never meant to publish. `.gitignore` already says what is not part of project; mdwiki honours it. Every hide rule except two is author-negotiable in `mdwiki.yml`. Hidden files never vanish silently: `mdwiki validate` says what was hidden and why.

### Decisions (agreed in review)

1. Honour `.gitignore`. Own matcher in mdwiki, no new runtime dependency, no `git` binary needed at runtime. `git check-ignore` is test oracle only.
2. Other `*ignore` files (`.eslintignore`, `.prettierignore`, `.forceignore`) not read. Their meaning is "don't lint/format/deploy", not "don't publish".
3. `validate` reports hidden paths: compact summary plus actionable link error; never counted by `--strict`.
4. Manifest keys toggle dot-path rule and `.gitignore` rule, add extra excludes, and list explicit includes. `.git/` and `mdwiki.yml` always hidden, no override.

### Solution Design

**Matcher (own parser).** Implement gitignore rules from `gitignore(5)`:

- Blank lines and `#` comments skipped; `\#` and `\!` escape; trailing unescaped spaces stripped.
- `!` negates; last matching pattern wins.
- Pattern with `/` at start or middle anchored to its `.gitignore` directory; otherwise matches at any depth.
- Trailing `/` matches directories only.
- `*` and `?` do not cross `/`; `[...]` classes; leading `**/`, trailing `/**`, middle `/**/`.
- Git rule: file cannot be re-included if a parent directory is excluded. Walk must honour it (stop descending ignored dirs).
- Nested `.gitignore` applies to its own subtree, deeper file overrides shallower.

Compile each pattern to one regex once; cache per directory keyed on `.gitignore` mtime/size so edits take effect without restart (same approach as title cache on review branch).

**Test oracle.** Fixture corpus: tree of files plus `.gitignore` files covering every rule above (and nasty cases: `foo/**/bar`, `!` under ignored dir, trailing spaces, escaped `#`). Test runs `git init` in tmp dir, `git check-ignore --no-index -v --stdin` over every path, compares with mdwiki matcher. Skip test with clear reason when `git` not on PATH. Also randomized test: generate patterns plus paths, diff against git. Git is test-time only, never imported or required at runtime.

**Hide predicate.** One function, `is_hidden(relpath, rules) -> reason | None`, reasons: `always` (`.git/`, `mdwiki.yml`), `dot-path`, `gitignore`, `exclude`. Order:

1. Hard floor: `.git` segment anywhere, or path equals loaded config file. Hidden, no override.
2. `include` match: visible.
3. `exclude` match, `.gitignore` match (if `use_gitignore`), dot segment (if `hide_dot_paths`): hidden with that reason.

On review branch this is `paths.is_hidden` (commit `27b59d9`), already called by routing, raw files, listings, search, ordering, validate, build. Build this item on top of that commit; on bare master it means first introducing the single predicate.

**Config.** Keys optional, defaults keep today's dot behaviour plus gitignore on. `exclude` / `include` must be lists of strings, else config error at load (not silent). `include` pattern resolving into hard floor gives validate warning (`include` cannot publish `.git/` or `mdwiki.yml`).

**Validate.** Summary groups hidden paths by top-level entry: `node_modules/: 1243 pages and 9 files hidden (.gitignore)`. Shown after issues, separate block, never counted as warning for `--strict`. Link from served page to hidden page: existing "does not resolve" error plus `(hidden by .gitignore)`.

**Order of work (small commits):** matcher plus oracle tests; config keys; predicate wiring; validate summary and link reason; README section.

**Behaviour change, author-visible:** with `use_gitignore: true` default, a page that is gitignored but was served before disappears. Validate summary makes it visible; README notes it.

Contracts: none across domains. `SiteConfig` fields new, additive.

Closes Page Routing fragility point: "Exclusion list hardcoded ... dot-segment rule ... are code literals. New excluded type = code edit. Direction: move to config key."
